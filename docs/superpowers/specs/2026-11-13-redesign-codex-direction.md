# 화면 다시 디자인하기 — 코덱스 안

2026-11-13. 이승열 P가 미리보기를 보고 "모두 다 디자인 요소라는 게 아예 없었다. 그냥 글자만 나열된 느낌"이라고 했다.
코덱스(디자인 담당)의 검토와 시안을 본 뒤 **"코덱스 안으로 가자"**로 정했다.

## 정한 것

- 화면 모양과 구성은 코덱스 시안을 따른다. 시안 4장(학생 홈, 학생 주보, 주보 작성, 중등부 안내)과 검토 글은
  작업 중에는 `.superpowers/design-review/codex/`에 있고, 구현이 끝나면 `docs/design.md`가 정본이 된다.
- 남색·금색·고운바탕·프리텐다드는 유지한다. 바꾸는 것은 구성과 꾸밈이다:
  표어 "동행하는 자" 그림 표지, 구역마다 다른 면(소식은 금빛, 함께 나누는 소식은 연한 녹색), 광고의 날짜 덩어리,
  펼쳐 보는 구역, 세 칸을 지키는 예배 순서표.
- 피할 것: 밋밋하고 글자만 줄지어 있는 화면, 요란하고 산만한 화면.
- 그림은 새로 만든 것을 쓴다(코덱스가 만든 `walking-together`). 교회 로고와 사진은 받는 대로 넣는다 — 받기 전에는 사진 자리를 화면에 두지 않는다.

## 범위

1. **보는 화면**: 학생 홈, 학생·교사 주보 탭(중등부 안내 포함). 시안 그대로.
2. **주보 작성**: 설교 제목·본문을 맨 먼저. 순서 12줄은 요약 줄, 누른 줄만 펼쳐 고친다. 노트북에서는 구역 목록 + 표 편집.
   아래 저장 줄에 고칠 곳으로 가는 안내. 다음 주 예배위원, 출석·새 친구·생일도 요약 먼저.
3. **저장 약속을 바꾼다**(코덱스가 꼽은 가장 위험한 문제): "초안 저장"은 게시된 주보를 내리지 않는다. "게시 내리기"는 따로 둔다.
4. **중등부 안내 관리**: 구역별 구성, 노트북에서는 학생에게 보일 모습 미리보기.
5. **화면 폭**: 관리자 화면은 노트북에서 넓게(최대 약 1,248px). 학생·교사 홈과 주보는 900px 이상에서 시안대로 2열(최대 약 1,080px) — 본문 열은 읽기 편한 폭(640px 안팎)을 지킨다.
6. **나머지 화면**(말씀, 기도, 나, 출석, 우리 반, 관리 메뉴, 학생 명단, 로그인): 같은 디자인 말씨로 맞춘다. 구조는 크게 바꾸지 않는다.

## 하지 않는 것

- 공개 범위 규칙은 그대로다(헌금 명단 없음, 학생 화면에 반별 이름 명단 없음, 이름·개인 번호는 잠긴 문서, 공개 문서에 반 ID 없음, 자물쇠 그림 없음).
- 학생 명단의 큰 개편(검색, 새 친구 반영 상태 추적)은 이번에 하지 않는다. 새 친구 안내 문구만 분명히 한다.
- 연속 출석 축하를 홈에서 빼지 않는다(코덱스는 '나' 탭으로 옮기자고 했지만, 있던 기능을 없애는 일이라 따로 여쭌다).

## 저장 약속(3번)의 설계

- 새 문서 `bulletinDrafts/{date}` — 관리자만 읽고 쓴다. 주보 칸과 새 친구·생일을 함께 담는다(관리자만 보므로).
- 초안 저장: 이 문서만 쓴다. `bulletins/{date}`는 건드리지 않는다.
- 게시: `bulletins/{date}`(published: true) + `members/main` 쓰기 + 초안 지우기를 한 배치로.
- 게시 내리기: `bulletins/{date}`의 `published`를 false로(지금 '임시저장'이 하던 일을 이름 그대로).
- 작성 화면이 여는 순서: 초안 → 없으면 `bulletins/{date}`. 예전에 '임시저장'으로 남은 미게시 주보는 그대로 초안처럼 읽힌다(옮기지 않는다).
- 상태 표시: 새 주보 / 초안 / 게시 중 / 게시 중(고친 초안 있음).
- 규칙을 바꾸므로 `tests/rules`에 시험을 더한다. 초안 문서는 교사(관리자 아님)·학생·로그인 없는 사람이 읽지 못한다.

## 누가 무엇을

- **코덱스**: 화면 구현(토큰·공통 부품·그림·화면·`docs/design.md`). 자기 시안이 기준이다.
- **Claude**: 저장 약속의 자료·규칙·시험, 화면 시험이 뜻을 잃지 않는지 검토, 공개 범위 점검, 마지막 전체 검토.
- 같은 폴더에서 차례로 일한다(시험용 서버 포트를 함께 쓰기 때문).
