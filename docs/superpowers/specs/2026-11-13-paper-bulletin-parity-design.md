# 종이 주보 맞추기 — 설계

2026-11-13 · 근거 자료: `~/Downloads/261115 중등부 주보.pdf`(2026-41호, 2쪽)

## 왜

이승열 P가 실제 중등부 종이 주보를 보여 주며 두 가지를 원했다.

1. 앱의 예배 순서가 종이 주보의 예배 순서와 **같은 모양**이기를.
2. 종이 주보에만 있는 정보를 **앱에서도 확인**할 수 있기를.

## 정한 것(이승열 P 결정)

- 공개 범위(추천안 그대로 승인)
  - **헌금하신 분 명단**: 앱에 올리지 않는다(저장하지도 않는다).
  - **반별 학생 명단**: 학생 화면에 싣지 않는다(선생님 화면에는 이미 반 명단이 있다). 학생 화면에는 **반별 출석 인원 숫자만**.
  - **연락처**: 교회 대표번호는 누구나, **개인 전화번호는 학생 링크를 받은 사람(학생 세션)과 선생님만**.
- 만드는 방법은 **A안**: 매주 바뀌는 것은 주보에, 거의 안 바뀌는 것은 관리 화면의 "중등부 안내" 한 장에. 출석 인원·새 친구는 앱 자료로 자동 계산.
- 교사 출석 수(종이의 "교사 13/15")는 앱이 기록하지 않으므로 주보 편집 화면에서 손으로 적는다.
- **새 친구는 명단에 올릴 때 "새 친구" 체크**로 가린다(추천안 승인). 체크된 학생이 처음 출석한 주의 주보에 자동으로 오른다. 처음 명단을 한꺼번에 넣을 때는 체크하지 않는다.

## 방법 비교(기록)

| 안 | 내용 | 버린 이유 |
|---|---|---|
| **A (채택)** | 주보 문서 확장 + 고정 정보는 "중등부 안내" 한 장 + 비공개 정보는 따로 잠근 문서 | — |
| B | 모든 것을 매주 주보 한 장에 | 고정 정보가 매주 복사되고, 고치면 지난 주보는 옛 정보로 남음. 개인 번호만 따로 감출 수 없어 결국 A처럼 나눠야 함 |
| C | 종이 주보 PDF·사진 올리기 | 휴대폰에서 읽기 어렵고, 헌금 명단·명단이 그대로 공개되어 정한 공개 범위와 맞지 않음 |

## 목표 / 하지 않을 것 / 실패로 볼 것

- 목표: 학생이 앱 주보 탭만 보고도 종이 주보에서 얻던 정보(헌금 명단 빼고)를 얻는다. 관리자가 매주 하는 입력은 지금보다 크게 늘지 않는다.
- 하지 않을 것: 종이 주보 PDF·인쇄용 출력, 생일 **달력 격자**(목록으로 대신), 약도 이미지(주소 + 지도 링크로 대신), 헌금 기록 기능.
- 실패로 볼 것(작동해도):
  - 개인 전화번호·새 친구 이름·생일 명단이 **로그인 없는 공개 문서**(`bulletins`, `settings`)에 들어감.
  - 헌금 명단이 어디에든 저장됨.
  - 종이 주보의 청록색·손글씨 모양을 따라 해 지금 디자인("차분하고 단정한 교회", `docs/design.md`)을 흐트러뜨림. 종이와 맞추는 것은 **내용과 순서**이지 색·글꼴이 아니다.

## 현재 상태(바탕)

- `bulletins/{date}`: `order: OrderItem[]`(type·title·detail), `hymns`, `scripture`, `sermonTitle`, `published`… 게시된 것은 **누구나 읽음**(규칙).
- `settings/*`: 누구나 읽음, 관리자만 씀. 주보 기본 순서는 `settings/bulletinTemplate`, 없으면 `DEFAULT_ORDER`.
- 학생 세션: 학생 링크를 연 기기가 익명 로그인 → `studentSessions/{uid} = {token}`. 규칙 헬퍼 `sessionOf(uid)`, `studentOf(token)`이 있다. 읽기 화면은 세션을 기다리지 않는다(`useStudentSession`).
- 운영 DB(`mjc-jungdeungbu`)에는 아직 주보·학생·반·설정 문서가 **하나도 없다**(2026-11-13 확인) → 자료 옮기기(마이그레이션) 불필요. 다만 시험·에뮬레이터 시드의 옛 모양은 새 모양으로 고친다.

## 설계

### 1. 예배 순서를 종이와 같게

- `OrderItem`에 `standing?: boolean`(일어서서) 추가. 화면에서는 순서 이름 앞에 `*`, 순서표 위에 "*표는 일어서서" 안내. 화면 읽기 프로그램에는 "일어서서"로 읽힌다(별표는 aria-hidden).
- 한 줄 = **순서 · 내용 · 맡은 사람**. 기존 `type`=순서, `title`=내용(찬송·본문·설교 제목 등), `detail`=맡은 사람으로 쓴다(필드 이름은 그대로, 편집 화면 라벨만 "순서 / 내용 / 맡은 사람"으로). 지금 보기(`BulletinView`)는 "순서 ····· 내용/맡은 사람"인데, 종이처럼 **순서 | 내용 | 맡은 사람** 세 칸이 되게 바꾼다. 좁은 화면(360px)에서는 순서·맡은 사람이 한 줄, 내용이 그 아래 줄로 내려가도 된다(빌더 판단).
- `DEFAULT_ORDER`를 종이 주보 순서로 바꾼다(★=standing):
  경배와 찬양 · ★신앙고백(사도신경) · ★영광찬송 · ★합심기도 · ★기도 · 봉헌 · 성경봉독 · 설교 · ★찬송 · ★축복기도 · 소식나눔 · 축하나눔
  - 기본값의 내용·맡은 사람: 신앙고백 "사도신경 / 다함께", 영광찬송·합심기도·성경봉독·찬송 "다함께", 경배와 찬양 맡은 사람 "리조이스 찬양팀", 소식나눔 맡은 사람 "김형준 부장님", 축하나눔 "학생임원". 나머지는 비움. (기본값일 뿐, 관리자가 템플릿으로 저장해 바꿀 수 있다.)
- 주보 문서에 새 칸:
  - `leader: string` — 인도자("정한결 선생님"). 순서표 머리에 "인도: …".
  - `opening: { text: string; ref: string }` — 여는 말씀("하나님은 영이시니…", "요 4:24"). 순서표 머리 아래.
  - `issue: string` — 호수("2026-41호"). 주보 머리 날짜 옆. 새 주보를 만들 때 바로 앞 주보의 호수에서 끝 숫자를 1 올려 미리 채운다(고칠 수 있음).
- 기존 `hymns`·`scripture`·`sermonTitle`은 그대로 둔다(홈 카드 제목·지난 주보 목록·설교 링크가 이 칸을 쓴다). **겹침 처리(내 판단)**:
  - 보기에서 순서 이름이 "성경봉독"인 줄의 내용이 비어 있으면 `scripture`를, "설교"인 줄의 내용이 비어 있으면 `sermonTitle`(없으면 설교 문서 제목)을 대신 보여 준다. 저장되는 값은 바꾸지 않는다(보기에서만 채움). 순서 이름 비교는 앞뒤 공백·가운데 공백을 무시("성경 봉독"도 같음).
  - 그렇게 순서표에 본문·설교 제목이 실제로 보였으면, 아래 "말씀" 구역에서 그 항목은 빼고(둘 다 빠지면 구역 숨김), 설교 상세 링크는 순서표 설교 줄의 내용에 건다.
  - 순서 이름을 바꾼 템플릿에서 위 이름이 없으면 지금처럼 "말씀" 구역에 보인다.
- 학생 화면에서 순서표 구역 제목은 "주일예배".

### 2. 매주 바뀌는 덧붙임(주보 문서, 공개)

공개 문서에 넣어도 되는 것만:

- `nextServers: { role: string; name: string }[]` — "다음 주 예배위원"(인도: 한가람 학생 / 기도: 서다온 학생). 예배 순서에 이미 학생 이름(봉헌자 등)이 공개로 나가고 있으므로 같은 수준으로 본다.
- `attendance: AttendanceSummary | null` — 지난 주 출석 인원:
  ```ts
  interface AttendanceSummary {
    sunday: string;                 // 센 주일(yyyy-mm-dd)
    classes: { name: string; present: number; total: number }[];  // 반 ID는 넣지 않는다(아래)
    students: { present: number; total: number };
    teachers: { present: number; total: number } | null; // 손으로 적음, 비우면 안 보임
  }
  ```
  학생 화면: "지난 주(10.25) 출석 — 학생 33/55 · 교사 13/15", 그 아래 반별 "1-1 5/8 …". **이름은 없다.**
  **반 문서 ID도 없다.** 반 ID는 그 반의 기도 제목(`classes/{classId}/prayers`, ID를 아는 사람에게 공개)을 여는 유일한 열쇠라서, 누구나 읽는 공개 문서에는 반 ID를 절대 넣지 않는다 — 반 줄은 이름과 인원만. 앱은 `saveBulletin` 에서 이름·인원만 다시 골라 담고, 규칙은 `attendance` 의 키를 `sunday, classes, students, teachers` 로 제한한다(목록 원소는 규칙이 볼 수 없다). 반 줄이 하나도 없으면 출석을 싣지 않는다(학생 0/0 금지).

### 3. 매주 바뀌는 비공개 덧붙임(잠긴 문서)

`bulletins/{date}/members/main` (새 문서):

- `newFriends: string[]` — 새 친구(푸른열매) 이름.
- `birthdays: { name: string; date: string /* mm-dd */ }[]` — 이번 달 생일.

읽기: 선생님, 또는 **활성 학생 세션**(아래 규칙). 쓰기: 관리자. 주보가 임시저장(`published:false`)이면 학생은 못 읽는다(부모 주보 규칙과 맞춤).

### 4. 자동 계산(주보 편집 화면의 "불러오기")

주보 편집 화면에 **"출석·새 친구·생일 불러오기"** 버튼. 누르면 아래를 계산해 폼에 채우고, 관리자가 고친 뒤 저장한다(저장된 값이 정본 — 나중에 출석을 고쳐도 지난 주보는 바뀌지 않는다). 새 주보를 처음 열 때 한 번 자동으로 불러와도 된다(빌더 판단).

- **센 주일** = 주보 날짜보다 앞선 주일 중 출석 기록이 있는 가장 최근 주일.
- **반별 출석** = 그 주일 `present:true` 수 / 그 반의 활성 학생 수(지금 기준). 반 순서는 `classes.order`.
- **새 친구** = 학생 문서의 `newcomer == true`(명단에 올릴 때 "새 친구" 체크)이면서, 그 주일에 출석했고 **그 전에 출석(present:true) 기록이 없는** 학생. 체크된 학생만 이전 기록을 확인하면 된다.
  - `Student`에 `newcomer?: boolean` 추가. 관리 → 명단의 한 명 추가 폼과 학생 상세 수정에 "새 친구" 체크칸(기본 꺼짐). 여러 명 한꺼번에 넣기에는 두지 않는다.
  - `newcomer`는 관리자만 쓴다(기존 students 규칙: 관리자 무엇이든, 반 교사는 streak·lastPresent만 — 그대로 지켜진다). 학생 화면에는 이 값을 보이지 않는다.
- **이번 달 생일** = 주보 날짜가 속한 달에 생일이 있는 활성 학생(날짜순).
- 교사 출석 수는 계산하지 않는다(빈칸, 손으로).

### 5. 중등부 안내(거의 안 바뀜)

관리 화면에 새 구역 **"중등부 안내"**(`src/admin/sections.ts`에 추가). 두 문서로 나눈다.

- `settings/info` — 공개(기존 settings 규칙 그대로):
  - `motto: { title: string; subtitle: string; verse: string; ref: string }` — "동행하는 자" / "하나님과 동행하며 내 이웃과 동행하는 사람" / 미가 6:8 본문 / "미가 6:8".
  - `etiquette: string[]` — 예배 에티켓 줄들(예배 전 자기 점검 질문 포함, 들여쓰기는 없음 — 한 줄씩).
  - `place: { name: string; address: string; mapUrl: string }` — 오시는 길. `mapUrl`은 관리자가 붙여 넣는 지도 링크(없으면 버튼 숨김).
  - `churchPhone: string` — 교회 대표번호.
- `memberInfo/main` — 잠김(새 컬렉션):
  - `servants: { role: string; names: string }[]` — 섬기는 분들(교장·담당·부장·부감·총무·서기·회계, 찬양팀, 학생 임원). 학생 임원 이름이 들어가므로 잠근다.
  - `contacts: { label: string; phone: string }[]` — 개인 연락처("이승열 목사님 010-…").

### 6. 화면 배치(학생 주보 탭, 선생님 주보 탭 공통)

주보 카드 한 장 안의 순서:

1. 머리: 날짜 주일 · 호수
2. 주일예배(인도·여는 말씀·순서표·"*표는 일어서서")
3. 찬양 / 말씀(비면 숨김, 지금 그대로)
4. 광고(지금 그대로)
5. 다음 주 예배위원
6. 지난 주 출석
7. 🔒 새 친구 · 이번 달 생일 (잠긴 문서를 읽을 수 있을 때만; 못 읽으면 구역 자체를 그리지 않는다. 세션이 아직 준비 중이면 준비되면 나타난다)

그 아래 별도 카드 **"중등부 안내"**: 표어 → 🔒 섬기는 분들 → 예배 에티켓 → 오시는 길(지도 열기) → 연락처(대표번호는 누구나, 🔒 개인 번호는 세션·선생님만). 전화번호는 `tel:` 링크.

디자인은 `docs/design.md` 토큰·규칙을 그대로 따른다(새 색 없음, 구역 제목 고운바탕, 숫자 프리텐다드). 자물쇠 아이콘은 화면에 그리지 않는다(🔒는 이 문서의 표시일 뿐).

### 7. 규칙(`firestore.rules`)

- 새 헬퍼 `isMember()` = `request.auth != null && exists(studentSessions/{auth.uid}) && studentOf(sessionOf(auth.uid).data.token).data.active == true`.
- `bulletins/{date}/members/{id}`: get = `isTeacher() || (isMember() && 부모 주보 published == true)`; 쓰기 = `isAdmin() && isDateId(date)`. list 불필요.
- `memberInfo/{id}`: get = `isTeacher() || isMember()`; 쓰기 = `isAdmin()`.
- 주보 새 칸 모양 검사는 기존 주보 규칙 수준(관리자만 씀)이면 충분. 단 `bulletins/{date}` 문서에 `newFriends`·`birthdays`·`contacts` 같은 키가 **들어가지 않게** 허용 키 목록을 둔다(실패 조건 보호).
- 각 규칙에 `tests/rules` 시험 추가(세션 없는 익명·비활성 학생 세션·다른 학생 세션·선생님·관리자).

### 8. 시험

- 단위: 출석 요약·새 친구·생일 계산(경계: 출석 기록 없는 주, 처음 나온 학생, 비활성 학생, 달 경계), 호수 +1, 새 순서 기본값.
- 규칙: 위 7.
- e2e: 관리자가 주보(인도·여는 말씀·일어서서·예배위원·불러오기)와 중등부 안내를 저장 → 학생 링크(새 컨텍스트 `openStudent`)에서 보임, 개인 번호·새 친구는 세션 준비 뒤 보임. 공개 주보 화면은 만들지 않으므로(내 판단), "링크 없이는 못 읽음"은 화면이 아니라 규칙 시험(로그인 없는 클라이언트의 Firestore 직접 읽기 거부)으로 확인한다.
- 화면 확인: `scripts/shots.mjs`로 학생·관리 화면 360px, 밝음·어두움.
