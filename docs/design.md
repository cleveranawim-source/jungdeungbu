# 디자인 시스템 — 함께 걷는 주보

다음 화면을 만드는 사람은 이 문서와 `src/ui/theme.css`를 기준으로 작업한다. 2026-11-13 이승열 P가 고른 코덱스 시안을 실제 앱으로 옮긴 방향이다. 11월 10일에 고른 남색·금색·고운바탕은 유지하되, 장식을 사실상 금지하던 규칙은 폐기한다. **차분함은 밋밋함을 뜻하지 않는다.** 표지 그림, 글자 크기의 대비, 넓은 색 면, 서로 다른 구역 구성이 있어야 한다.

## 1. 구성 원칙

- **주보는 한 장의 편집된 프로그램이다.** 동행 그림 표지 → 구역 바로가기 → 예배 순서 → 이번 주 소식 → 함께 나누는 소식 → 지난 주 함께한 인원 → 중등부 안내 → 지난 주보 순으로 읽는다. 모든 것을 같은 흰 상자에 넣지 않는다.
- **색 면은 정보의 성격을 보여 준다.** 남색 표지와 표어, 종이 같은 예배 순서, 금빛 소식 머리, 연녹색 환영·생일·축하, 바탕색 위 출석 요약을 구별한다. 색을 보지 못해도 제목과 내용으로 구역을 이해할 수 있어야 한다.
- **그림은 의미가 있어야 한다.** 올해 표어와 연결되는 동행 그림을 홈·주보의 표지에 쓴다. 안내의 작은 길 곡선은 같은 이야기의 장식이다. 화면마다 임의의 그림·패턴·이모지·그라데이션을 추가하지 않는다. 실사진과 로고를 받기 전에는 사진 자리나 가짜 사진을 만들지 않는다.
- **한 손으로 읽고 누른다.** 360px부터 가로 스크롤이 없어야 한다. 본문 17px, 모든 링크·버튼 최소 44×44px. 부가 자료는 요약부터 보여 주고 필요한 사람이 펼친다.
- **노트북 폭도 사용한다.** 홈·학생 주보·교사 주보는 900px 이상에서 최대 1080px, 본문과 공개 안내를 2열로 배치한다. 본문 한 열은 약 640px 이하로 읽기 편한 폭을 유지한다. 안내가 전혀 없으면 빈 옆 열을 남기지 않는다. 900px 미만은 최대 640px 단일 열이다.
- **개인 정보가 없어도 완결된다.** 구성원 세션이 준비되기 전이나 실패한 경우 새 친구·생일·섬기는 분들·개인 연락처는 구역째 빠진다. 오류·자물쇠·빈 자리로 그 존재를 알리지 않는다. 공개 안내가 옆 열의 중심이다.

### 글꼴과 크기

- `--font-display`: **Gowun Batang**, 번들 패키지 400·700. 화면 제목, 주요 구역 제목, 표어·표지. `font-synthesis: none`.
- `--font-body`: **Pretendard Variable / Pretendard**, 번들 동적 서브셋. 본문·입력·버튼·탭·숫자·순서표·disclosure 요약. 외부 글꼴 요청을 만들지 않는다.
- `--text-xs/sm/md/lg/xl/2xl`: 13/15/17/20/26/34px. 본문은 17, 보조 설명은 15, 표의 열 머리·배지는 13. 입력칸은 17.
- `--text-cover` 34px, `--text-cover-small` 28px(399px 이하), `--text-cover-wide` 48px. 표지 제목은 text-wrap: balance로 한 글자만 남는 줄을 피한다. 단순히 모든 제목을 키우지 않고 그림 표지의 중심 문장에만 쓴다.
- `--text-display` 56px은 첫 화면의 큰 “중등부”에만 쓰는 기존 값이다.
- 본문 행간 1.65, 제목 1.3. 한글 `word-break: keep-all`, 긴 주소·긴 단어는 `overflow-wrap: anywhere`로 처리한다. 한 글자만 남는 줄과 그림 위 겹침을 실제로 확인한다.
- 표어 위의 작은 머리말은 두지 않는다. 제목이 의미를 전달하게 하고, 장식은 누르는 행·chevron 위를 지나지 않게 한다.

### 간격과 크기

`--space-1`…`--space-8` = 4/8/12/16/20/24/32/48px. 화면 좌우 16, 카드 내부 20, 읽기 구역 사이 20~24, 큰 구분은 32. 표 셀은 좁은 화면에서 5px의 열 간격을 예외로 쓴다.

`--radius-sm/md/lg` = 6/10/14px, `--radius-cover` = 16px. 모든 것을 둥근 알약으로 만들지 않는다. `--content-max` = 640px, `--reading-layout-max` = 1080px, `--admin-layout-max` = 1248px. 기본 터치 높이 `--touch` = 48px, 최소 `--touch-min` = 44px. 탭 바 56px + safe-area, 화면 끝에 탭 바만큼 여백을 둔다.

## 3. 읽는 화면의 구성

### 학생 홈

Screen의 h1은 “이름, 반가워요”. 표어를 담은 그림 표지 → 이번 주 날짜·호수·말씀 제목·본문 → “이번 주 주보 보기”를 하나의 표지로 연결한다. 세션에 관계없이 읽을 수 있는 공개 안내의 표어만 사용한다. 표어를 아직 못 받으면 “함께 드리는 예배”로 완성된 표지를 보여 준다.

표지 아래 말씀·기도 바로가기, 공개 장소·지도·교회 전화 안내를 두고, 기존 생일·연속 출석 축하를 연녹색 띠로 유지한다. 축하 기준은 `src/lib/celebrate.ts` 그대로다. 이번 주 소식은 금빛 머리와 안내 기간로 구별한다. 넓은 화면에서는 표지·축하 왼쪽, 소식 오른쪽. 주보가 없으면 기존 준비 안내와 소식이 남는다.

### IllustratedCover

`<IllustratedCover title subtitle>`는 그림과 실제 텍스트를 분리한다. 이미지에는 `alt=""`, `srcSet` 480/800/1280, 용도에 맞는 `sizes`가 있다. 전화 화면의 그림은 약 15~28KB이며 가장 큰 것도 약 50KB다. 원래 PNG를 번들에 싣지 않는다. 생성 출처는 같은 폴더의 `prompt.txt`에 둔다.

그림의 오른쪽 인물·길과 왼쪽 남색 텍스트 영역을 지킨다. 어두운 모드에서도 그림 위 밝은 글자의 대비를 유지한다. 글자 뒤는 남색으로 덮고 가장자리만 투명하게 연결하는 보호 그라데이션을 사용한다. 시선을 끌기 위한 별도의 그라데이션 장식과 구별한다. 긴 표어·부제를 잘라 감추지 않는다. 변하는 문장 길이에 대해 360px 렌더링을 검사한다.

### 주보 표지와 순서표

표지는 날짜와 “주일예배”, 짧은 안내 문장, 교회명·호수로 구성한다. **설교 제목과 본문은 순서표에서 한 번만 보여 준다.** `displayOrder`가 채운 항목은 별도 말씀 구역에 다시 쓰지 않는다. 표지에 설교 제목을 중복시키지 않는다.

`SectionJump`는 예배 순서·소식·안내 중 실제로 있는 구역만 보여 준다. 이 앱은 hash 라우터이므로 `href="#구역"`을 쓰지 않는다. 버튼이 대상에 초점을 옮기고 스크롤한다. reduced-motion이면 즉시 이동한다.

순서표는 `<table aria-label="예배 순서">`, 세 열 **순서 | 내용 | 맡은 사람**. 열 머리는 `scope="col"`, 순서 이름은 `scope="row"`. 360px에서도 27% / 46% / 27% 열을 유지한다. 내용이 길면 **자기 셀 안에서** 줄바꿈하고 표를 가로로 스크롤시키지 않는다. 순서·맡은 사람 15px, 내용 17px. 담당자는 오른쪽 맞춤. 설교 링크의 누를 수 있는 높이는 44px 이상이다.

여는 말씀은 은은한 면과 들여쓰기, 출처로 구별한다. 출처만 있으면 빈 본문 단락을 만들지 않는다. 별표가 있는 행에는 화면 읽기용 “일어서서”가 있고, 아래에 “* 표가 있는 순서에는 함께 일어서요.”를 표시한다. 빈 추가 구역은 생략한다.

### 이번 주 소식과 안내 기간

`NewsSection`의 h2 머리에 금빛 면을 쓴다. 광고는 제목과 본문을 먼저 읽고, 아래에 작은 보조 글자로 “11월 29일까지 알려요”를 표시한다. **endDate는 광고 노출 기간이며 행사 날짜가 아니다.** 큰 날짜 블록과 앞자리 0은 쓰지 않는다. 실제 행사 날짜 필드가 생기기 전에는 본문에서 행사일을 추측하지 않는다.

“다음 주 예배위원”은 같은 소식 구역 아래 요약으로 접혀 있다. 펼치면 역할과 이름을 두 열로 읽는다. 개인 세션 게이트와 기존 공개 범위는 바꾸지 않는다.

### 함께 나누는 소식과 인원

새 친구·생일은 연녹색 한 구역 안에서 각각 이름과 날짜로 묶는다. 두 목록이 모두 없으면 전체 구역이 없다. 이름은 세션 게이트가 통과시킨 문서에서만 온다.

“지난 주 함께한 인원”에는 날짜와 **학생 33 / 55명**, 교사 합계를 먼저 보여 준다. 분자는 크게, 숫자는 Pretendard tabular-nums. “반별 인원 보기”를 펼치면 반 이름 / 함께한 인원 / 전체 인원 표가 나온다. **반별 학생 이름과 반 ID는 DOM에 싣지 않는다.** 출석 자료가 없거나 학생 전체가 0이면 구역이 없다.

### 중등부 안내와 지난 주보

`InfoCard`의 공개 구성은 제목 → 남색 표어 패널(긴 표어 말씀은 펼쳐 읽기) → 오시는 길·지도 보기·교회 전화 → 예배 에티켓. 섬기는 분들·선생님 연락처는 준비된 memberInfo가 있을 때만 추가한다. 예배 에티켓·섬기는 분들·선생님 연락처는 각각 접혀 있다. 시간은 아직 자유 입력 안내에 포함되어 있으므로 임의로 추출하거나 고정 시간을 만들어 표시하지 않는다.

지도는 `safeHttpUrl`을 통과한 주소만 새 창 링크로, 번호는 `telHref`가 되는 경우 44px `tel:` 링크로 쓴다. 안내가 완전히 비면 카드와 바로가기 모두 없다. 넓은 화면에서는 공개 안내가 오른쪽, 주보 본문이 왼쪽이다. 지난 주보는 주보와 안내 아래 독립 disclosure이며 기존 날짜 필터링을 유지한다.

## 4. 공통 컴포넌트

- **Screen**: h1은 이 컴포넌트만 그린다. 기본 최대 640px. 읽기 화면은 `layout="reading"`으로 900px 이상에서 최대 1080px. `tabBar`를 전달하면 안전한 아래 여백을 마련한다. 관리 화면은 `layout="admin"`, 900px 이상 최대 1248px이다.
- **Card**: 묶음 하나의 기본 흰 면·얇은 선. `title`은 h2. `accent`는 조용한 강조, `quiet`는 개발용·보조. 카드 안에 카드를 계속 쌓지 않는다. 표지·소식·안내처럼 의미가 다른 구역은 전용 컴포넌트로 표현한다.
- **Disclosure**: h2/h3 안의 실제 button과 연결된 hidden 패널, 기본 접힘. 버튼 전체 최소 48px, 제목+선택적 요약+chevron. `aria-expanded`/`aria-controls`로 상태와 패널을 연결한다. 제목을 summary 안에 넣지 않아 iOS 화면 읽기에서도 단계가 유지되게 한다. Enter/Space로 펼친다. 고정 높이·잘린 내부 스크롤을 만들지 않는다. 남색 표어 면에서는 `tone="cover"`로 밝은 글자·구분선·초점 색을 사용한다.
- **Button / LinkButton**: primary는 중요한 행동 하나, secondary는 보조, ghost는 덜 중요한 행동, danger는 삭제. 높이 48px(sm44/lg56), 아이콘 전용은 이름과 44×44 영역 필수. 이동에는 링크, 동작에는 버튼. busy는 중복 입력을 막는다.
- **Field / TextArea**: 항상 보이는 라벨, 17px 입력. placeholder는 예시. 오류는 빨간 선뿐 아니라 문구·아이콘·aria-invalid·설명 연결로 표현한다.
- **TabBar**: 학생 홈/주보/말씀/기도/나, 교사 출석/우리 반/기도/주보/관리. 하단 고정, 선택 탭은 남색 굵은 글자와 금색 밑줄. 화살표·Home·End로 이동한다. 기존 역할과 이동 방식을 유지한다.
- **Toast / OfflineBar**: App에서 공통 제공. 토스트 info3.5초/error6초, 오류는 `describeError`를 거친다. 세션 게이트 안내의 부재는 의도적 예외이며 오류 토스트를 만들지 않는다.
- **EmptyState**: 지금 상태 + 다음 행동. 공개 데이터 없음과 구성원 데이터 준비 중을 혼동하지 않는다.
- **CelebrationBanner**: 기존 생일·4주 단위 연속 출석 규칙을 보존. sage 색 쌍, 움직임 없음. 기존 🎂/🔥 축하 문구는 유지한다.
- **아이콘**: `Icon`의 일관된 선 아이콘. 글자 옆 아이콘은 읽기에서 숨김, 단독으로 뜻을 전할 때는 이름을 준다. 장식 그림·길 패턴도 읽기에서 숨긴다.
- **AttendanceCalendar**: 기존 출석 채움/나머지 옅은 점 규칙과 접근성 이름을 유지한다. 결석을 탓하는 시각 표현을 추가하지 않는다.

## 5. 관리 작성 화면

### 공통 작업 셸과 저장 줄

900px 미만은 한 열, 900px 이상은 최대 1248px이다. 900–1199px에서는 구역 목록을 위 가로줄로 두어 입력 표의 폭을 확보하고, 1200px부터 왼쪽에 둔다. `EditorLayout`은 구역 이동 목록과 넓은 작업 면을 제공한다. 휴대폰의 구역 목록은 “작성 구역”으로 접는다. 구역 이동은 해시 주소를 바꾸지 않고 제목에 초점을 옮긴다. `EditorSection`의 말씀 머리는 금빛, 구성원 소식 머리는 연녹색이다. 기본 입력 면은 카드색으로 두어 색의 짝과 대비를 유지한다.

관리 메뉴와 글로벌 탭 바를 유지한다. 저장 줄(`EditorBar`)은 탭 바 위에 붙으며, 넓은 화면에서는 상태 왼쪽·버튼 오른쪽으로 배치한다. 토스트를 자기 높이만큼 올려 버튼을 가리지 않는다. 저장 안 한 내용/저장된 내용과 같음을 글자로 표시한다. 오류가 있으면 문제 이름과 “고칠 곳으로” 버튼을 보여 준다. 누르면 해당 펼침 구역을 열고 첫 오류 칸에 초점을 옮긴다. 입력칸의 aria-invalid/설명/오류 문구도 유지한다. 다른 메뉴나 날짜로 나갈 때는 기존 이동 확인을 거친다.

### 주보 작성

날짜·호수·저장 상태 → 이번 주 말씀(설교 제목·성경 본문, 호수·인도자·여는 말씀) → 예배 순서 → 찬양 → 광고 → 다음 주 예배위원 → 출석·새 친구·생일 → 게시 전 미리보기 순서다.

- `OrderEditor`: 휴대폰에서 요약 줄(번호·순서·실제 표시 내용·담당자·일어서서)을 누르면 한 행의 입력만 펼친다. 900px 이상에서는 같은 입력 DOM을 인라인 표로 펼친다. 순서 이름/내용/담당자/일어서서/이동·삭제의 열을 유지한다. 성경봉독·설교의 빈 내용은 `displayOrder`로 실제 값을 보여 주고 “이번 주 말씀에서 가져와요”라고 안내한다. 내용을 직접 적으면 그 값이 우선이다.
- “지난 주에서 가져오기”는 이전 게시본의 순서(일어서기 포함)·찬양만 복사하며 되돌릴 수 있다. “기본 순서 저장”은 다음 새 주보의 기본 순서를 바꾼다. 새 주보는 기본 순서와 직전 게시본의 다음 호수로 시작한다.
- 찬양·다음 주 예배위원은 요약부터 보여 준다. 예배위원에는 **다음 주일 날짜**를 적는다. 광고는 선택한 주일에 나갈 소식을 읽기 형태로 보여 준다. “광고 관리”로 다녀올 때는 선택한 주일과 기기의 미저장 복구본을 유지한다.
- 출석은 **불러오기 버튼을 눌러야** 채워진다. 출석 기준 주일·학생 합계 먼저, 반별 숫자는 펼쳐 고친다. 교사 수는 손으로 적으며 둘 다 비우면 싣지 않는다. 잘못 적은 숫자를 0으로 바꾸지 않는다. 새 친구·생일은 인원 요약 아래 펼침 안에서 여러 줄 붙여넣기를 유지한다. 잘못된 생일 줄은 저장을 막는다. 반드시 `readExtras` 경로로 변환해 반 ID가 공개 주보에 들어가지 않게 한다.
- “게시 전 미리보기”는 실제 `BulletinView`와 `InfoCard`를 사용한다. 개인 링크 화면/공개 안내만을 바꿔 볼 수 있다. 미리보기만 열었다고 저장되지는 않는다.

| 상태 | 의미와 행동 |
|---|---|
| 새 주보 | 아직 서버 내용이 없음 |
| 초안 | 새 초안, 내린 주보 또는 예전 미게시 문서. 학생에게 없음 |
| 게시 중 | 학생이 보는 게시본과 작성 기준이 같음 |
| 게시 중 · 고친 초안 있음 | 학생은 게시본을 계속 보고, 관리자는 새 초안을 편집함 |

“초안 저장” → “초안을 저장했어요”, “게시” → “게시했어요”로 문구를 맞춘다. 초안 저장은 `saveBulletinDraft`만 호출하며 게시본을 바꾸지 않는다. 게시는 `publishBulletin`의 원자적 배치로 게시본·구성원 소식과 초안을 처리한다. 타임스탬프가 있는 경우 경과 시간을 보여 주며 API에 없는 저장자 이름은 추측하지 않는다.

“게시 관리”는 보조 펼침이다. “게시 내리기”는 학생에게서 숨기지만 내용을 남긴다는 확인을 거친다. “초안 버리기”는 돌아갈 게시본이 있을 때만 나타나며 서버 초안과 기기의 편집 내용을 버린다는 확인을 거친다. 단순히 초안을 저장해 게시본을 내리는 동작은 없다. 저장 중에도 더 적은 내용은 남는다. `jdb:draft:*` 복구본·로그아웃 시 삭제·깨진 복구본 거절을 유지한다.

### 중등부 안내 관리

올해 표어 / 예배 시간과 에티켓 / 오시는 길 / 섬기는 분들 / 연락처로 나눈다. 긴 설명·말씀·교사 이름은 여러 줄 입력이다. 공개 구역은 “누구나 볼 수 있어요”, 사람 이름·개인 번호 구역은 “학생 링크를 받은 사람과 선생님만 볼 수 있어요”를 적는다. 예배 시간은 기존 etiquette 줄에 작성하며 새 저장 필드를 만들지 않는다.

저장은 **모든 주보의 안내에 적용**된다고 머리와 저장 줄에 안내한다. `saveInfo`의 한 배치로 공개 안내와 개인 안내를 분리 저장한다. 잘못된 지도 링크는 아무것도 저장하지 않고 해당 칸으로 안내한다. 900px 이상은 실제 학생용 안내를 옆에서 바로 미리 본다. 900–1199px은 구역 목록을 위 가로줄로 두어 입력 폭을 확보하고, 1200px부터 왼쪽 구역 목록·입력·미리보기의 3열이다.

그 외 관리 화면은 이 단계에서 최대 960px으로 제한해 과도한 폭을 막는다. 관리 메뉴는 넓은 화면에서 2열이다. 명단·반·교사·광고 등의 세부 시각 개선은 Phase 3 범위다.

## 6. 문구·접근성·검증

문구는 친근한 “~해요”, 짧고 구체적으로. 버튼은 “올리기/저장/지도 보기”처럼 결과를 예측할 수 있게 쓴다. 결석이나 실수를 탓하지 않는다. 신앙 내용은 작성된 말씀·기도에 맡기고 UI가 과장된 설교를 덧붙이지 않는다.

움직임은 누름·펼침·상태 변화에만 쓴다. `--dur-press/fast/base` 90/160/240ms. reduced-motion이면 즉시/1ms로 끝낸다. 자동 등장·반복 흔들기·시선 끄는 애니메이션은 없다.

다음 화면의 완료 조건:

- h1 하나, h2/h3 순서, 표/목록 이름과 행·열 관계를 유지한다.
- 실제로 누르는 모든 영역은 최소 44px, 키보드 초점은 모든 면에서 보인다.
- 360·390px 밝음/어두움, 1280px 밝음을 실제 앱으로 캡처해 본다. 긴 제목·긴 이름·빈 배열·선택 구역 부재도 검사한다.
- 세션 실패 시 공개 부분은 완결되고 개인 구역·개인 번호·이름·반 ID가 DOM에 새지 않는다. 헌금 명단은 어디에도 없다.
- 번들 글꼴·최적화 그림만 요청한다. 사진 자리·시안 링크·검토용 문구가 앱에 없다.
- `typecheck`, unit(디자인 가드·모든 색 쌍 대비 포함), rules/data, e2e, build가 통과한다. 구조나 문구를 바꿀 때 e2e의 기존 의미를 지키면서 선택자만 맞춘다.
- `firebase/firestore`를 화면에서 직접 import하지 않고 data API를 사용한다. 읽기 디자인 변경 때문에 저장·공개 범위·필터링 동작을 바꾸지 않는다.


### Phase 1 리뷰 반영

공개 장소·지도·교회 전화는 `PlaceInfo` 한 부품에서 같은 URL/전화 검사를 사용한다. 개인정보 번호도 그 부품의 `PhoneLink`를 사용한다. 홈의 표어는 장식 문단, 이번 주 설교 제목은 h2다. 공개 안내를 함께 읽은 뒤 홈을 그려 임시 표어가 깜빡이지 않게 한다. 안내 카드는 주보 읽기가 끝나기 전에 별도 위치에 먼저 나타나지 않는다. 보조 열이 없으면 화면 제목까지 본문과 같은 폭으로 정렬한다. 표지의 소개 문구·교회 이름은 호출하는 화면이 brand 설정으로 전달한다. 다크 모드의 그림 바탕과 표지 아래 면은 같은 남색을 쓴다.
