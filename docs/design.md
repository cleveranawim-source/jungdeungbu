# 디자인 시스템 — 함께 걷는 주보

다음 화면을 만드는 사람은 이 문서와 `src/ui/theme.css`를 기준으로 작업한다. 2026-11-13 이승열 P가 고른 코덱스 시안을 실제 앱으로 옮긴 방향이다. 11월 10일에 고른 남색·금색·고운바탕은 유지하되, 장식을 사실상 금지하던 규칙은 폐기한다. **차분함은 밋밋함을 뜻하지 않는다.** 표지 그림, 글자 크기의 대비, 넓은 색 면, 서로 다른 구역 구성이 있어야 한다.

## 1. 구성 원칙

- **주보는 한 장의 편집된 프로그램이다.** 동행 그림 표지 → 구역 바로가기 → 예배 순서 → 이번 주 소식 → 함께 나누는 소식 → 지난 주 함께한 인원 → 중등부 안내 → 지난 주보 순으로 읽는다. 모든 것을 같은 흰 상자에 넣지 않는다.
- **색 면은 정보의 성격을 보여 준다.** 남색 표지와 표어, 종이 같은 예배 순서, 금빛 소식 머리, 연녹색 환영·생일·축하, 바탕색 위 출석 요약을 구별한다. 색을 보지 못해도 제목과 내용으로 구역을 이해할 수 있어야 한다. 일반 관리 폼·목록의 머리는 기본 카드 면과 얇은 구분선을 쓰며, 모든 구역을 금빛·연녹색으로 채우지 않는다.
- **그림은 의미가 있어야 한다.** 올해 표어와 연결되는 동행 그림을 첫 화면·로그인·홈·주보의 표지에 쓴다. 안내의 작은 길 곡선은 같은 이야기의 장식이다. 화면마다 임의의 그림·패턴·이모지·그라데이션을 추가하지 않는다. 실사진과 로고를 받기 전에는 사진 자리나 가짜 사진을 만들지 않는다.
- **한 손으로 읽고 누른다.** 360px부터 가로 스크롤이 없어야 한다. 본문 17px, 모든 링크·버튼 최소 44×44px. 부가 자료는 요약부터 보여 주고 필요한 사람이 펼친다.
- **노트북 폭도 사용한다.** 학생·교사의 읽기 화면은 900px 이상에서 최대 1080px, 본문과 공개 안내를 2열로 배치한다. 본문 한 열은 약 640px 이하로 읽기 편한 폭을 유지한다. 안내가 전혀 없으면 빈 옆 열을 남기지 않는다. 900px 미만은 최대 640px 단일 열이다.
- **개인 정보가 없어도 완결된다.** 구성원 세션이 준비되기 전이나 실패한 경우 새 친구·생일·섬기는 분들·개인 연락처는 구역째 빠진다. 오류·자물쇠·빈 자리로 그 존재를 알리지 않는다. 공개 안내가 옆 열의 중심이다.

작성 구역의 보조 설명에는 `--muted`를 금빛·연녹색 면 위에 사용할 수 있다. 두 모드의 `muted/gold-panel`, `muted/sage-bg`와 삭제 버튼의 `danger-ink/danger` 대비도 시험에 고정한다. 같은 범위의 CSS 선택자는 한 규칙에서 관리하며, 모듈 CSS가 참조하는 토큰은 theme.css 또는 실제 런타임 style 선언에 있어야 한다.

그림자는 카드에 쓰지 않는다(`--shadow-card: none`). `--shadow-float`는 떠 있는 시트·토스트에만 쓴다.

### 글꼴과 크기

- `--font-display`: **Gowun Batang**, 번들 패키지 400·700. 화면 제목, 주요 구역 제목, 표어·표지. `font-synthesis: none`.
- `--font-body`: **Pretendard Variable / Pretendard**, 번들 동적 서브셋. 본문·입력·버튼·탭·숫자·순서표·disclosure 요약. 외부 글꼴 요청을 만들지 않는다.
- `--text-xs/sm/md/lg/xl/2xl`: 13/15/17/20/26/34px. 본문은 17, 보조 설명은 15, 표의 열 머리·배지는 13. 입력칸은 17.
- `--text-cover` 34px, `--text-cover-small` 28px(399px 이하), `--text-cover-wide` 48px. 표지 제목은 text-wrap: balance로 한 글자만 남는 줄을 피한다. 단순히 모든 제목을 키우지 않고 그림 표지의 중심 문장에만 쓴다.
- `--text-display` 56px은 첫 화면의 큰 “중등부”에만 쓰는 기존 값이다.
- 본문 행간 1.65, 제목 1.3. 한글 `word-break: keep-all`, 긴 주소·긴 단어는 `overflow-wrap: anywhere`로 처리한다. 한 글자만 남는 줄과 그림 위 겹침을 실제로 확인한다.
- 표어 위의 작은 머리말은 두지 않는다. 제목이 의미를 전달하게 하고, 장식은 누르는 행·chevron 위를 지나지 않게 한다.

### 간격과 크기

`--space-1`…`--space-8` = 4/8/12/16/20/24/32/48px. 화면 좌우 16, 카드 내부 20, 읽기 구역 사이 20~24, 큰 구분은 32. 표 셀은 좁은 화면에서 5px의 열 간격을 예외로 쓴다.

`--radius-sm/md/lg` = 6/10/14px, `--radius-cover` = 16px. 모든 것을 둥근 알약으로 만들지 않는다. `--content-max` = 640px, `--reading-layout-max` = 1080px, `--admin-layout-max` = 1248px. 기본 터치 높이 `--touch` = 48px, 최소 `--touch-min` = 44px. 탭 바 56px + safe-area, 화면 끝에 탭 바만큼 여백을 둔다.

## 3. 읽는 화면의 구성

### 학생 홈

Screen의 h1은 “이름, 반가워요”. 표어를 담은 그림 표지 → 이번 주 날짜·호수·말씀 제목·본문 → “이번 주 주보 보기”를 하나의 표지로 연결한다. 세션에 관계없이 읽을 수 있는 공개 안내의 표어만 사용한다. 공개 안내를 함께 읽은 뒤 홈을 그려 임시 표어가 깜빡이지 않게 한다. 안내가 없거나 읽기에 실패하면 “함께 드리는 예배”로 완성된 표지를 보여 준다. 홈의 표어는 장식 문단이고 이번 주 설교 제목은 h2다.

표지 아래 말씀·기도 바로가기, 공개 장소·지도·교회 전화 안내를 두고, 생일 축하만 연녹색 띠로 보여 준다. 생일이 주일 ±3일 안에 없으면 띠와 여백 모두 생략한다. 연속 출석 축하는 첫 화면에 표시하지 않고 나 탭의 출석 기록에 둔다. 축하 기준은 `src/lib/celebrate.ts` 그대로다. 이번 주 소식은 금빛 머리와 안내 기간으로 구별한다. 넓은 화면에서는 표지·축하 왼쪽, 소식 오른쪽. 주보가 없으면 기존 준비 안내와 소식이 남는다.

### IllustratedCover

`<IllustratedCover title subtitle>`는 그림과 실제 텍스트를 분리한다. 이미지에는 `alt=""`, `srcSet` 480/800/1280, 용도에 맞는 `sizes`가 있다. 전화 화면의 그림은 약 15~28KB이며 가장 큰 것도 약 50KB다. 원래 PNG를 번들에 싣지 않는다. 생성 출처는 같은 폴더의 `prompt.txt`에 둔다.

그림의 오른쪽 인물·길과 왼쪽 남색 텍스트 영역을 지킨다. 어두운 모드에서도 그림 위 밝은 글자의 대비를 유지한다. 글자 뒤는 남색으로 덮고 가장자리만 투명하게 연결하는 보호 그라데이션을 사용한다. 시선을 끌기 위한 별도의 그라데이션 장식과 구별한다. 긴 표어·부제를 잘라 감추지 않는다. 변하는 문장 길이에 대해 360px 렌더링을 검사한다.

홈·로그인은 기존 큰 표지를 유지하고, 주보는 `compact` 표지를 쓴다. 주보 그림 영역은 모바일 최소 160px, 600px 이상 200px이며 하단 메타 패딩은 12px이다. 고정 높이로 긴 제목을 자르지 않는다. 다크 모드도 그림 바탕과 표지 아래 면을 같은 남색으로 연결한다. 표지의 소개 문구·교회 이름은 호출 화면의 brand 설정으로 전달한다.

### 주보 표지와 순서표

표지는 날짜와 “주일예배”, 짧은 안내 문장, 교회명·호수로 구성한다. 그림은 작은 표지로 보여 순서표가 첫 화면에 들어오게 한다. 여는 말씀은 별도 채움 상자 없이 8px 세로 패딩으로 가운데 정렬한다. **설교 제목과 본문은 순서표에서 한 번만 보여 준다.** `displayOrder`가 채운 항목은 별도 말씀 구역에 다시 쓰지 않는다. 표지에 설교 제목을 중복시키지 않는다.

`SectionJump`는 예배 순서·소식·안내 중 실제로 있는 구역만 보여 준다. 이 앱은 hash 라우터이므로 `href="#구역"`을 쓰지 않는다. 버튼이 대상에 초점을 옮기고 스크롤한다. reduced-motion이면 즉시 이동한다.

순서표는 `<table aria-label="예배 순서">`, 세 열 **순서 | 내용 | 맡은 사람**. 열 머리는 `scope="col"`, 순서 이름은 `scope="row"`. 360px에서도 27% / 46% / 27% 열을 유지한다. 내용이 길면 **자기 셀 안에서** 줄바꿈하고 표를 가로로 스크롤시키지 않는다. 순서·맡은 사람 15px, 내용 17px. 예배 순서 제목과 순서·내용 열의 머리 및 모든 행은 가운데, 인도자와 담당자는 오른쪽 맞춤이다. 설교 링크의 누를 수 있는 높이는 44px 이상이다.

여는 말씀은 본문과 출처를 가운데로 맞춘다. 출처만 있으면 빈 본문 단락을 만들지 않는다. 별표가 있는 행에는 화면 읽기용 “일어서서”가 있고, 아래에 “* 표가 있는 순서에는 함께 일어서요.”를 표시한다. 빈 추가 구역은 생략한다.

### 이번 주 소식과 안내 기간

`NewsSection`의 h2 머리에 금빛 면을 쓴다. 광고는 제목과 본문을 먼저 읽고, 아래에 작은 보조 글자로 “11월 29일까지 알려요”를 표시한다. **endDate는 광고 노출 기간이며 행사 날짜가 아니다.** 큰 날짜 블록과 앞자리 0은 쓰지 않는다. 실제 행사 날짜 필드가 생기기 전에는 본문에서 행사일을 추측하지 않는다.

“다음 주 예배위원”은 같은 소식 구역 아래 요약으로 접혀 있다. 펼치면 역할과 이름을 두 열로 읽는다. 개인 세션 게이트와 기존 공개 범위는 바꾸지 않는다.

### 함께 나누는 소식과 인원

새 친구·생일은 연녹색 한 구역 안에서 각각 이름과 날짜로 묶는다. 두 목록이 모두 없으면 전체 구역이 없다. 이름은 세션 게이트가 통과시킨 문서에서만 온다.

“지난 주 함께한 인원”에는 날짜와 **학생 33 / 55명**, 교사 합계를 먼저 보여 준다. 분자는 크게, 숫자는 Pretendard tabular-nums. “반별 인원 보기”를 펼치면 반 이름 / 함께한 인원 / 전체 인원 표가 나온다. **반별 학생 이름과 반 ID는 DOM에 싣지 않는다.** 출석 자료가 없거나 학생 전체가 0이면 구역이 없다.

### 중등부 안내와 지난 주보

`InfoCard`의 공개 구성은 제목 → 남색 표어 패널(긴 표어 말씀은 펼쳐 읽기) → 오시는 길·지도 보기·교회 전화 → 예배 에티켓. 섬기는 분들·선생님 연락처는 준비된 memberInfo가 있을 때만 추가한다. 예배 에티켓·섬기는 분들·선생님 연락처는 각각 접혀 있다. 시간은 아직 자유 입력 안내에 포함되어 있으므로 임의로 추출하거나 고정 시간을 만들어 표시하지 않는다.

안내 카드는 주보 읽기가 끝나기 전에 별도 위치에 먼저 나타나지 않는다. 공개 장소·지도·교회 전화는 `PlaceInfo`, 개인 번호도 같은 `PhoneLink`를 써서 URL/전화 검사를 공유한다. 지도는 `safeHttpUrl`을 통과한 주소만 새 창 링크로, 번호는 `telHref`가 되는 경우 44px `tel:` 링크로 쓴다. 안내가 완전히 비면 카드와 바로가기 모두 없다. 넓은 화면에서는 공개 안내가 오른쪽, 주보 본문이 왼쪽이다. 보조 열이 없으면 화면 제목도 본문과 같은 폭으로 정렬한다. 지난 주보는 주보와 안내 아래 독립 disclosure이며 기존 날짜 필터링을 유지한다.


### 말씀·기도

말씀 목록은 날짜를 왼쪽 월/일 블록으로 맞추고 제목·본문 출처·두 줄 요약을 오른쪽에 둔다. 여기의 날짜는 실제 설교 날짜다. 화면 읽기에는 월과 일의 단위를 모두 제공한다. 첫 항목 제목은 더 크게, 넓은 화면에서는 나머지 항목을 두 열로 펼친다. 상세는 640px 읽기 폭, 금빛 제목 면·요약·문단·연녹색 적용 질문 순서다. 긴 본문은 1.85 행간과 문단 여백으로 읽는다.

기도는 작성 폼의 제목을 “작은 마음도 함께 나눠요”로 통합하고 별도의 소개 카드·“기도 제목 올리기” 머리를 반복하지 않는다. 한 문장 안내 바로 아래 입력칸과 공개 범위 선택이 나오고, 다음 구역은 우리 반 목록이다. 목록이 비면 카드 안에 또 카드를 넣지 않고, 20px 기도 아이콘과 h3 상태 문장·다음 행동을 카드 본문에 바로 표시한다. 900px 이상에서는 두 구역이 나란히 놓이므로 안내 문구는 “위에서” 같은 위치 표현을 쓰지 않는다. `누가 볼까요`의 우리 반/선생님만과 기존 공개 범위는 그대로다. 선생님 기기는 작성할 수 없다는 설명을 유지한다.

### 나

나 화면은 남색 이름·반·생일 면과 금빛 머리의 출석 기록을 나란히 배치한다. 연속 출석이 1주 이상이면 기존 요약행을 보여 주고, 0주이면 요약행 자체를 생략해 빈 간격을 남기지 않는다. 최근 출석을 바탕으로 4·8·12…주 조건을 만족할 때만 요약행 아래에 달력 선 아이콘과 “N주째 함께 예배했어요”를 작은 보조 글자로 표시한다. 비교·순위·유지 압박 없이 함께한 시간을 인정하는 한 줄이다. 해당하지 않으면 축하 문장이나 빈자리가 없다. 학기 출석 횟수와 달력은 이 조건과 관계없이 그대로 보여 준다. 달력은 달마다 행을 나누고 날짜의 출석 채움·미출석 점을 그대로 둔다.

### 교사 출석·우리 반·기도

출석은 주일/반 선택을 16px 패딩의 작은 작업 면에 묶고, 인원 합계와 현재 반 이름을 학생 목록 머리에 둔다. 별도의 큰 소개·인원 색 면을 쌓지 않는다. 반 하나면 선택기를 생략하고, 두세 반은 칩, 네 반 이상은 48px 기본 선택 칸을 쓴다. 선택 칸의 DOM 값은 반 ID가 아닌 배열 순번이며 반 이름만 표시한다. 우리 반·교사 기도에도 같은 선택기를 쓴다. 선택은 남색(다크에서는 금색) 채움과 체크를 함께 쓴다. 휴대폰 두 열, 넓은 화면 세 열의 이름 버튼과 왼쪽 날짜/반 선택을 배치한다. 누르기·취소·대기 중 저장·생일·연속 출석 표시는 기존 의미를 유지한다.

우리 반은 안내→반 고르기→학생 목록이며 이름을 누르면 출석 달력과 링크 공유를 볼 수 있다. 넓은 화면의 목록은 두 열이다. 상세는 남색 학생 정보와 출석 달력·링크 공유로 구성한다. 기도 화면은 우리 반에 나눈 기도(연녹색)와 선생님께만 보낸 기도(금빛)를 나란히 놓는다. 공개 범위 문장을 반드시 유지하고 선생님 전용 표시에는 편지 아이콘을 쓴다. 자물쇠 아이콘은 쓰지 않는다.

### 입구와 공통 상태

첫 화면은 동행 그림·교회 이름과 학생 링크 안내/내 화면 열기, 선생님 로그인으로 구성한다. 로그인은 그림 표지와 실제 로그인 행동을 분리하며 초대받은 Google 계정이라는 조건을 먼저 알린다. 앱 안 브라우저의 주소 복사/외부 브라우저 안내는 그대로 둔다. 초대 없는 계정은 이메일과 로그아웃, 잘못된 학생 링크는 선생님께 새 링크를 요청하는 설명과 첫 화면 이동을 제공한다.

`PageIntro`는 20px 제목·15px 설명과 24px 선 아이콘의 낮은 안내다. 색 면은 40px 아이콘 자리 안에만 쓰고 전체 소개를 큰 색 카드로 감싸지 않는다. 실제 말씀 제목보다 안내 제목을 키우지 않는다. 장식적인 별도 머리말은 넣지 않는다. 빈 상태는 카드색 면, 연녹색 아이콘, 상태 제목, 다음 행동으로 구성한다. 불러오기 실패는 같은 구조에서 오류 설명과 다시 불러오기 버튼을 제공한다. `describeError`의 read 문맥은 “연결을 확인한 뒤 다시 불러와 주세요”, 기본 쓰기 오류는 “연결을 확인한 뒤 다시 시도해 주세요”로 안내한다. 일반 오류가 자동 저장을 보장하지 않는다. 로딩은 status 영역과 작은 회전 표시이며 움직임 줄이기를 존중한다. 오프라인 띠는 화면 위, 토스트는 하단 탭과 저장 줄 위에 둔다. 상태는 색과 아이콘만으로 전달하지 않는다.

## 4. 공통 컴포넌트

- **Screen**: 앱 화면의 h1을 그린다. 독립 입구인 Landing/InvalidLink는 자체 h1 하나를 가진다. 기본 최대 640px. 읽기 화면은 `layout="reading"`으로 900px 이상에서 최대 1080px. `tabBar`를 전달하면 안전한 아래 여백을 마련한다. 관리 화면은 `layout="admin"`, 900px 이상 최대 1248px이다.
- **Card**: 묶음 하나의 기본 흰 면·얇은 선. `title`은 h2. `accent`는 조용한 강조, `quiet`는 개발용·보조. `gold`/`sage`는 제목 띠만 해당 색 쌍으로 채우고 내용은 카드색에 둔다. `work`는 관리 폼·목록용으로 17px Pretendard 600 제목, 기본 카드 면과 얇은 구분선을 쓴다. 카드 안에 카드를 계속 쌓지 않는다. 표지·소식·안내처럼 의미가 다른 구역은 전용 컴포넌트로 표현한다.
- **Disclosure**: h2/h3 안의 실제 button과 연결된 hidden 패널, 기본 접힘. 버튼 전체 최소 48px, 제목+선택적 요약+chevron. `aria-expanded`/`aria-controls`로 상태와 패널을 연결한다. 제목을 summary 안에 넣지 않아 iOS 화면 읽기에서도 단계가 유지되게 한다. Enter/Space로 펼친다. 고정 높이·잘린 내부 스크롤을 만들지 않는다. 남색 표어 면에서는 `tone="cover"`로 밝은 글자·구분선·초점 색을 사용한다.
- **Button / LinkButton**: primary는 중요한 행동 하나, secondary는 보조, ghost는 덜 중요한 행동, danger는 삭제. 높이 48px(sm44/lg56), 아이콘 전용은 이름과 44×44 영역 필수. 이동에는 링크, 동작에는 버튼. busy는 중복 입력을 막는다.
- **Field / TextArea**: 항상 보이는 라벨, 17px 입력. placeholder는 예시. 오류는 빨간 선뿐 아니라 문구·아이콘·aria-invalid·설명 연결로 표현한다.
- **TabBar**: 학생 홈/주보/말씀/기도/나, 교사 출석/우리 반/기도/주보/관리. 하단 고정, 선택 탭은 `TabIcon`의 채움형 아이콘(밝은 모드 남색, 어두운 모드 금색), 굵은 글자와 금색 밑줄로 표시한다. 비선택 탭은 선 아이콘이며, 24px 크기를 유지한 채 짧은 불투명도 전환으로 바뀐다. 움직임 줄이기를 존중한다. 화살표·Home·End로 이동한다. 기존 역할과 이동 방식을 유지한다.
- **Toast / OfflineBar**: App에서 공통 제공. 토스트 info3.5초/error6초, 오류는 `describeError`를 거친다. 세션 게이트 안내의 부재는 의도적 예외이며 오류 토스트를 만들지 않는다.
- **EmptyState**: 지금 상태 + 다음 행동. 공개 데이터 없음과 구성원 데이터 준비 중을 혼동하지 않는다.
- **CelebrationBanner**: 홈의 생일 전용 띠. `birthdayCelebration`이 반환한 “이름, 생일을 축하해요”와 20px 케이크 선 아이콘을 8px 간격으로 배치한다. sage 색 쌍, 움직임 없음. 나의 연속 출석 문장은 `streakCelebration`을 따로 요청하고 출석 카드 안에서 20px 달력 아이콘·15px 보조 글자로 표시한다. 생일 ±3일, 연속 출석 4주 배수·최근 출석 규칙을 유지하며 둘 다 해당해도 화면별 문장만 보여 준다. 이모지·반말·느낌표를 섞지 않는다.
- **아이콘**: `Icon`의 일관된 선 아이콘. 글자 옆 아이콘은 읽기에서 숨김, 단독으로 뜻을 전할 때는 이름을 준다. 장식 그림·길 패턴도 읽기에서 숨긴다.
- **AttendanceCalendar**: 기존 출석 채움/나머지 옅은 점 규칙과 접근성 이름을 유지한다. 결석을 탓하는 시각 표현을 추가하지 않는다.

## 5. 관리 작성 화면

### 공통 작업 셸과 저장 줄

900px 미만은 한 열, 900px 이상은 최대 1248px이다. 900–1199px에서는 구역 목록을 위 가로줄로 두어 입력 표의 폭을 확보하고, 1200px부터 왼쪽에 둔다. `EditorLayout`은 구역 이동 목록과 넓은 작업 면을 제공한다. 휴대폰의 구역 목록은 “작성 구역”으로 접는다. 구역 이동은 해시 주소를 바꾸지 않고 제목에 초점을 옮긴다. `EditorSection`의 말씀 머리는 금빛, 구성원 소식 머리는 연녹색이다. 기본 입력 면은 카드색으로 두어 색의 짝과 대비를 유지한다.

관리 메뉴와 글로벌 탭 바를 유지한다. 저장 줄(`EditorBar`)은 탭 바 위에 붙으며, 넓은 화면에서는 상태 왼쪽·버튼 오른쪽으로 배치한다. 토스트를 자기 높이만큼 올려 버튼을 가리지 않는다. 저장 안 한 내용/저장된 내용과 같음을 글자로 표시한다. 오류가 있으면 문제 이름과 “고칠 곳으로” 버튼을 보여 준다. 누르면 해당 펼침 구역을 열고 첫 오류 칸에 초점을 옮긴다. 입력칸의 aria-invalid/설명/오류 문구도 유지한다. 저장 오류는 `EditorErrorLink` 하나의 status 영역으로 알리고 인원 줄마다 alert를 반복하지 않는다. 오류가 남아 있어도 패널을 닫을 수 있으며 안내를 다시 누르면 펼친다. 다른 메뉴나 날짜로 나갈 때는 기존 이동 확인을 거친다.

### 주보 작성

넓은 화면의 날짜 선택은 280–360px 영역에 두고 게시 상태를 옆에 배치한다. 이번 주 말씀의 제목/성경 본문, 여는 말씀/출처는 각각 길이에 맞춘 2열이며 모바일에서는 원래 읽기 순서대로 한 열이다.

날짜·호수·저장 상태 → 이번 주 말씀(설교 제목·성경 본문, 호수·인도자·여는 말씀) → 예배 순서 → 찬양 → 광고 → 다음 주 예배위원 → 출석·새 친구·생일 → 게시 전 미리보기 순서다.

- `OrderEditor`: 휴대폰에서 요약 줄(번호·순서·실제 표시 내용·담당자·일어서서)을 누르면 한 행의 입력만 펼친다. 900px 이상에서는 같은 입력 DOM을 인라인 표로 펼친다. 모바일에서는 표 역할을 presentation으로 내려 펼침 버튼과 라벨이 읽히게 하고, 넓은 화면은 실제 표 역할을 유지한다. 요약 버튼의 설명에 실제 내용·담당자·말씀 연결·일어서기를 연결한다. 정상적으로 비어 있는 내용은 경고 문장으로 채우지 않는다. 순서 이름/내용/담당자/일어서서/이동·삭제의 열을 유지한다. 성경봉독·설교의 빈 내용은 `displayOrder`로 실제 값을 보여 주고 “이번 주 말씀에서 가져와요”라고 안내한다. 내용을 직접 적으면 그 값이 우선이다.
- “지난 주에서 가져오기”는 이전 게시본의 순서(일어서기 포함)·찬양만 복사하며 되돌릴 수 있다. “기본 순서 저장”은 다음 새 주보의 기본 순서를 바꾼다. 새 주보는 기본 순서와 직전 게시본의 다음 호수로 시작한다.
- 찬양·다음 주 예배위원은 요약부터 보여 준다. 예배위원에는 **다음 주일 날짜**를 적는다. 광고는 선택한 주일에 나갈 소식을 읽기 형태로 보여 준다. “광고 관리”로 다녀올 때는 선택한 주일과 기기의 미저장 복구본을 유지한다.
- 출석은 **불러오기 버튼을 눌러야** 채워진다. 출석 기준 주일·학생 합계 먼저, 반별 숫자는 펼쳐 고친다. 교사 수는 손으로 적으며 둘 다 비우면 싣지 않는다. 잘못 적은 숫자를 0으로 바꾸지 않는다. 새 친구·생일은 인원 요약 아래 펼침 안에서 여러 줄 붙여넣기를 유지한다. 잘못된 생일 줄은 저장을 막는다. 반드시 `readExtras` 경로로 변환해 반 ID가 공개 주보에 들어가지 않게 한다.
- “게시 전 미리보기”는 실제 `BulletinView`와 `InfoCard`를 사용한다. 개인 링크 화면/공개 안내만을 바꿔 볼 수 있다. 미리보기만 열었다고 저장되지는 않는다.

| 상태 | 의미와 행동 |
|---|---|
| 새 주보 | 아직 서버 내용이 없음 |
| 초안 | 새 초안, 내린 주보 또는 예전 미게시 문서. 학생에게 없음 |
| 게시 중 | 학생이 보는 게시본과 작성 기준이 같음 |
| 게시 중 · 고친 초안 있음 | 학생은 게시본을 계속 보고, 관리자는 새 초안을 편집함 |

“초안 저장” → “초안을 저장했어요”, “게시” → “게시했어요”로 문구를 맞춘다. 초안 저장은 `saveBulletinDraft`만 호출하며 게시본을 바꾸지 않는다. 게시는 `publishBulletin`의 원자적 배치로 게시본·구성원 소식과 초안을 처리한다. 초안과 게시본이 함께 있으면 각각의 시각을 표시한다. 내린 주보는 “학생에게 보이지 않아요”라고 표시한다. 타임스탬프가 있는 경우 경과 시간을 보여 주며 API에 없는 저장자 이름은 추측하지 않는다.

“게시 관리”는 보조 펼침이다. “게시 내리기”는 학생에게서 숨기지만 내용을 남긴다는 확인을 거친다. “초안 버리기”는 돌아갈 게시본이 있을 때만 나타나며 서버 초안과 기기의 편집 내용을 버린다는 확인을 거친다. 단순히 초안을 저장해 게시본을 내리는 동작은 없다. 저장 중에도 더 적은 내용은 남는다. `jdb:draft:*` 복구본·로그아웃 시 삭제·깨진 복구본 거절을 유지한다. 복구본은 `{draftVersion:1,savedAt,value}`로 적으며 이전 형태도 읽는다. 서버 저장이 더 최근이면 복구 안내에서 경고하고 “되돌리기”로 서버 내용을 선택할 수 있다. 저장·상태는 useBulletinActions, 미리보기와 게시 관리는 각각의 부품으로 분리한다.

### 중등부 안내 관리

올해 표어 / 예배 시간과 에티켓 / 오시는 길 / 섬기는 분들 / 연락처로 나눈다. 긴 설명·말씀·교사 이름은 여러 줄 입력이다. 공개 구역은 “누구나 볼 수 있어요”, 사람 이름·개인 번호 구역은 “학생 링크를 받은 사람과 선생님만 볼 수 있어요”를 적는다. 예배 시간은 기존 etiquette 줄에 작성하며 새 저장 필드를 만들지 않는다.

저장은 **모든 주보의 안내에 적용**된다고 머리와 저장 줄에 안내한다. `saveInfo`의 한 배치로 공개 안내와 개인 안내를 분리 저장한다. 잘못된 지도 링크는 아무것도 저장하지 않고 해당 칸으로 안내한다. 900px 이상은 실제 학생용 안내를 옆에서 바로 미리 본다. 900–1199px은 구역 목록을 위 가로줄로 두어 입력 폭을 확보하고, 1200px부터 왼쪽 구역 목록·입력·미리보기의 3열이다.

### 나머지 관리 화면

관리 메뉴는 **이번 주 준비**(주보 작성·설교 작성·광고), **학생과 반**(학생 명단·반/교사·출석 현황), **상시 안내**(중등부 안내) 세 묶음이다. 첫 묶음 머리는 남색, 나머지는 기본 카드 면과 얇은 구분선이다. 기능 아이콘은 보조 글자색으로 표시한다. 각 행은 이름·구체적인 설명·기능 아이콘·이동 화살표로 구성한다. 900px 이상에서 두 열이며 주간 준비 묶음이 왼쪽을 차지한다.

학생 명단은 목록 왼쪽·학생 추가와 일괄 등록 오른쪽, 광고는 기존 목록 왼쪽·새 광고 오른쪽, 설교 작성은 본문 왼쪽·적용 질문 오른쪽이다. 반·교사는 반 목록/생성과 교사 초대/목록을 두 열로 나눈다. 출석 현황은 기간 전체 폭, 주일별·반별 표 나란히, 학생별 목록은 아래다. 모두 1248px 셸 안에서 입력 한 열을 읽기 좋은 폭으로 유지한다. 900px 미만에서는 원래 작업 순서의 한 열이다.

학생 새 친구 체크는 “새 친구로 맞이해요”, 힌트는 “첫 출석이 기록된 주의 주보에 불러올 수 있어요”다. 자동 게시로 오해할 문구를 쓰지 않는다. 체크·라디오·반 선택의 DOM 값은 표시용 인덱스이며 반 ID는 React 내부에서만 연결한다.

## 6. 문구·접근성·검증

문구는 친근한 “~해요”, 짧고 구체적으로. 버튼은 “올리기/저장/지도 보기”처럼 결과를 예측할 수 있게 쓴다. 결석이나 실수를 탓하지 않는다. 신앙 내용은 작성된 말씀·기도에 맡기고 UI가 과장된 설교를 덧붙이지 않는다.

움직임은 누름·펼침·상태 변화에만 쓴다. `--dur-press/fast/base` 90/160/240ms. reduced-motion이면 즉시/1ms로 끝낸다. 자동 등장·반복 흔들기·시선 끄는 애니메이션은 없다.

다음 화면의 완료 조건:

- h1 하나, h2/h3 순서, 표/목록 이름과 행·열 관계를 유지한다.
- 실제로 누르는 모든 영역은 최소 44px, 키보드 초점은 모든 면에서 보인다.
- 360·390px 밝음/어두움, 1280px 밝음을 실제 앱으로 캡처해 본다. 긴 제목·긴 이름·빈 배열·선택 구역 부재도 검사한다.
- 세션 실패 시 공개 부분은 완결되고 개인 구역·개인 번호·이름·반 ID가 DOM에 새지 않는다. 헌금 명단은 어디에도 없다.
- 번들 글꼴·최적화 그림만 요청한다. 사진 자리·시안 링크·검토용 문구가 앱에 없다.
- `typecheck`, unit(디자인 가드·모든 색 쌍 대비 포함), rules/data, e2e, build가 통과한다. 구조나 문구를 바꿀 때 e2e의 기존 의미를 지키면서 선택자만 맞춘다.
- `firebase/firestore`를 화면에서 직접 import하지 않고 data API를 사용한다. 읽기 디자인 변경 때문에 저장·공개 범위·필터링 동작을 바꾸지 않는다.


빌드에서는 Firebase SDK를 별도 `firebase` vendor 청크로 분리해 화면 수정 때 같은 SDK 파일을 재사용한다. 경로는 `/jungdeungbu/` base를 따르며 모든 화면은 계속 정적 import한다. 라우트 lazy-loading은 추가하지 않는다.
